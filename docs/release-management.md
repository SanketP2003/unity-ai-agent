# Release Management & Artifact Integrity Guide

Autonomous Game Studio provides enterprise-grade release pipeline controls, physical binary verification, and cryptographic tamper detection.

## Release Lifecycle State Machine

Releases progress strictly through an immutable state machine:

```text
       [DRAFT]
          │
          ▼
    [VALIDATING]
          │
     (Checks pass)
          ▼
  [READY_FOR_REVIEW]
          │
     (Human Approver)
          ▼
     [APPROVED]
          │
          ▼
     [PUBLISHED] ◄─── Strictly Immutable
      │        │
      │        └──► (Rollback) ──► [ROLLED_BACK]
      │
      └───────────► (Archive)  ──► [ARCHIVED]
```

### State Definitions
- **DRAFT**: Release candidate created, artifacts being registered.
- **VALIDATING**: Automated validation report generated by `CompletionGate`.
- **READY_FOR_REVIEW**: Awaiting authorized human review.
- **APPROVED**: Signed off by human reviewer (`ADMIN` or `REVIEWER`).
- **PUBLISHED**: Release sealed, immutable. Artifact pointers locked.
- **ROLLED_BACK**: Release demoted due to operational failure.
- **ARCHIVED**: Release retired into long-term cold storage.

---

## Physical Artifact Verification & SHA-256 Hashing

No release can be finalized with empty or phantom artifact references.
Every registered artifact (`.exe`, `.app`, `.zip`, `.unitypackage`) must satisfy:
1. **Physical On-Disk Existence**: File must exist on the local filesystem.
2. **Non-Zero Size**: `sizeBytes > 0`.
3. **Cryptographic Fingerprint**: SHA-256 checksum calculated at registration time and stored in the database.

---

## Tampering Detection & Defense

The system actively prevents post-publish modifications:
1. When `verifyArtifactIntegrity(artifactId)` is called:
   - The on-disk file is re-hashed using SHA-256.
   - The live digest is compared with the stored registration digest.
2. If any discrepancy is detected (e.g. byte injection, malware, file replacement):
   - The artifact state is immediately transitioned to `CORRUPTED`.
   - The release cannot be published or deployed.
   - Security alerts are logged.
3. If an on-disk binary is modified after a release is `PUBLISHED`:
   - Any attempt to link or publish subsequent releases using the corrupted artifact is hard-blocked.
   - The immutable published record preserves the original hash, exposing the tampering event.

---

## Human Approval Security Invariant

To guarantee that autonomous agents cannot self-authorize game releases:
- Reviewers with usernames containing `agent`, `llm`, or `autonomous-builder` are rejected by `ReleaseManager`.
- Only callers possessing `ADMIN` or `REVIEWER` roles may approve releases.
- LLMs are prohibited from calling approval APIs.
